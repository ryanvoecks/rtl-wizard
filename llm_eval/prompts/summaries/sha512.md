### Design summary

This is a hardware (Verilog) implementation of the **SHA-512 family of cryptographic hash functions** (the Secworks/Joachim Strömbergson core). It computes message digests over 1024-bit input blocks and supports four modes selectable at runtime: **SHA-512, SHA-384, SHA-512/224, and SHA-512/256**. It also includes an optional **"work factor"** feature that re-hashes a block a configurable number of times (a key-stretching / PoW-style hardening mechanism).

How it works: a software-facing top wrapper exposes a simple 32-bit memory-mapped register interface (control, status, block, digest). Internally, the core runs a 3-state FSM (IDLE → ROUNDS → DONE) executing the 80 SHA-512 compression rounds. Each round consumes one message-schedule word `W` (generated on the fly by a 16-entry sliding-window expander) and one round constant `K` (from a ROM), updating the eight 64-bit working variables `a..h` via the standard `T1`/`T2` round functions. After 80 rounds the running hash `H0..H7` is updated; with work factor enabled the block is re-processed `work_factor_num` times before finishing.

    ├── sha512_core.v          # Core compression engine + control FSM
    ├── sha512_w_mem.v         # Message schedule (W) sliding-window generator

### Key modules/files

- **`sha512.v` (module `sha512`)** — Top-level / integration point. Provides the external API: `clk, reset_n, cs, we, address[7:0], write_data[31:0], read_data[31:0], error`. Decodes register addresses (NAME/VERSION/CTRL/STATUS, 32×32-bit block words `0x10–0x2f`, 16×32-bit digest words `0x40–0x4f`, work-factor num). It assembles the 32 written block words into the wide `core_block[1023:0]`, latches the digest, and drives `init`/`next`/`mode`/`work_factor` into the core. Instantiates **`sha512_core`**.

- **`sha512_core.v` (module `sha512_core`)** — The heart of the design. Wide interface (`block[1023:0]` in, `digest[511:0]` out, plus `init/next/mode/ready/digest_valid`). Contains:
  - The working registers `a..h` and the persistent hash registers `H0..H7` (digest = concatenation of `H0..H7`).
  - Combinational **`t1_logic`** / **`t2_logic`** (Σ0, Σ1, Ch, Maj round functions) and **`state_logic`** (round update of `a..h`; init from H-constants on first block or from running hash on subsequent blocks).
  - **`digest_logic`** initializes/updates `H0..H7`.
  - Counters: `round_ctr` (0→79) and `work_factor_ctr`.
  - The main **`sha512_ctrl_fsm`** (IDLE/ROUNDS/DONE) sequencing rounds, re-running for work factor, and asserting `ready`/`digest_valid`.
  - Instantiates the three helper modules below.

- **`sha512_w_mem.v` (module `sha512_w_mem`)** — Message schedule generator. Holds 16×64-bit registers as a sliding window. On `init` it loads the 16 words of the input `block`; on `next` (once past index 15) it computes the next `W` word using the SHA-512 σ0/σ1 (ROTR/SHR) expansion `W = W0 + σ0(W1) + W9 + σ1(W14)` and shifts the window. Outputs the current `w[63:0]` consumed by the core's `T1`. Driven by `w_init`/`w_next` from the core FSM.

- **`sha512_k_constants.v` (module `sha512_k_constants`)** — Pure combinational ROM mapping the round counter `addr[6:0]` (0–79) to the 64-bit round constant `K`. Fed by the core's `round_ctr_reg`.

- **`sha512_h_constants.v` (module `sha512_h_constants`)** — Mode-dependent mux supplying the eight 64-bit initial hash constants `H0..H7` for the selected `mode` (512/224, 512/256, 384, 512). Used by the core both to seed the digest and to initialize `a..h` on the first block.

**Interaction flow:** `sha512.v` (bus/register layer) → `sha512_core.v` (FSM + datapath) → which pulls round constants from `sha512_k_constants`, initial values from `sha512_h_constants`, and expanded message words from `sha512_w_mem`. The mode-selection of SHA variant differs only in initial H values (`sha512_h_constants`) and, for the wrapper, which/how many digest bits are meaningful.
